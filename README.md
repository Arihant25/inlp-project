# Multilingual Code Learning Dynamics in LLMs

Investigating how code embedding models represent programming languages, frameworks, algorithmic complexity, and code correctness.

## Research Questions

| RQ      | Question                                                                                       |
| ------- | ---------------------------------------------------------------------------------------------- |
| **RQ1** | Are programming language families stable across embedding models, or representation-dependent? |
| **RQ2** | Do popular frameworks create detectable sub-clusters (dialects) within languages?              |
| **RQ3** | Is algorithmic complexity class a recoverable geometric signal in embeddings?                  |
| **RQ4** | Do correct and buggy implementations cluster separately in embedding space?                    |

## Setup

Requires Python 3.10+ and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/Arihant25/inlp-project.git
cd inlp-project
uv sync
```

For Ada-002 embeddings (optional), copy `.env.example` to `.env` and add your OpenRouter API key:

```bash
cp .env.example .env
# Edit .env and set OPENROUTER_API_KEY
```

## Embedding Models

All scripts accept `--model MODEL` where MODEL is one of:

| Key         | Model                         | Type             |
| ----------- | ----------------------------- | ---------------- |
| `octen`     | Octen/Octen-Embedding-0.6B    | Local            |
| `bge_m3`    | BAAI/bge-m3                   | Local            |
| `unixcoder` | microsoft/unixcoder-base      | Local            |
| `codebert`  | microsoft/codebert-base       | Local            |
| `qwen3`     | Qwen/Qwen3-Embedding-0.6B     | Local            |
| `minilm`    | all-MiniLM-L6-v2              | Local            |
| `ada002`    | openai/text-embedding-ada-002 | API (OpenRouter) |

Pass `--model all` (the default) to run all models sequentially.

## Reproducing Results

Each RQ follows a 4-step pipeline: **embed → analyze → visualize → cross-model comparison**. Run the steps in order since each depends on the previous one.

### RQ1: Model-Dependent Language Family Structure

Embeds 21 linguistic features across 19 languages, performs hierarchical clustering (Ward linkage), and measures cross-model agreement via Spearman correlation of distance matrices.

```bash
# Step 1: Generate embeddings from linguistic feature snippets
uv run code/embedding.py --model all

# Step 2: Hierarchical clustering + cross-model comparison
uv run code/clustering.py --model all
```

Dataset: `datasets/family_clustering/` (19 languages x 21 features).
Results go to `results/embeddings/` and `results/clustering/`.

> **Note:** The repo contains `code/finetune.py` for fine-tuning StarCoder on discovered families, but this was descoped — RQ1 showed that family assignments are representation-dependent (only 4 pairings stable across all 7 models), making family-based fine-tuning conclusions difficult to interpret causally.

### RQ2: Framework-Driven Dialects

```bash
uv run code/rq2/1_embedding.py --model all
uv run code/rq2/2_analysis.py --model all
uv run code/rq2/3_visualize.py --model all
uv run code/rq2/4_cross_model.py
```

Dataset: `datasets/RQ2/Extracted_Dataset/` (8 languages x 4 frameworks x 8 patterns x 4 variations, generated by Gemini 2.5 Pro).
Results go to `results/rq2/`.

### RQ3: Algorithmic Complexity Encoding

```bash
uv run code/rq3/1_embedding.py --model all
uv run code/rq3/2_analysis.py --model all
uv run code/rq3/3_visualize.py --model all
uv run code/rq3/4_cross_model.py
```

Dataset: `datasets/RQ3/` (150 LeetCode problems from NeetCode 150, 9 languages, 4,662 solutions with complexity annotations).
Results go to `results/rq3/`.

### RQ4: Correctness Regions & Bug Patterns

```bash
uv run code/RQ4/1_embedding.py --model all
uv run code/RQ4/2_analysis.py --model all
uv run code/RQ4/3_visualize.py --model all
uv run code/RQ4/4_cross_model.py
```

Dataset: `datasets/RQ4/bugs.json` (100 bug types x 5 languages x buggy/fixed pairs, generated by Gemini).
Results go to `results/RQ4/`.

## Project Structure

```text
code/
  embedding.py           # Core embedding generation (shared by all RQs)
  clustering.py          # RQ1 hierarchical clustering & cross-model agreement
  model_distance.py      # Cross-model distance matrix comparison
  rq2/                   # RQ2 pipeline (1_embedding → 4_cross_model)
  rq3/                   # RQ3 pipeline
  RQ4/                   # RQ4 pipeline

datasets/
  family_clustering/     # RQ1: 19 languages x 21 linguistic feature snippets
  RQ1/                   # Code-summary pairs (19 languages, used by finetune.py)
  RQ2/Extracted_Dataset/ # Framework-specific code snippets
  RQ3/                   # LeetCode problem files with complexity annotations
  RQ4/bugs.json          # Buggy-fixed code pairs

results/                 # All outputs (metrics JSON, plots, reports)
```
