# Multilingual Code Learning Dynamics in LLMs

Investigating how code embedding models represent programming languages, frameworks, algorithmic complexity, and code correctness.

## Research Questions

| RQ      | Question                                                                                       |
| ------- | ---------------------------------------------------------------------------------------------- |
| **RQ1** | Are programming language families stable across embedding models, or representation-dependent? |
| **RQ2** | Do popular frameworks create detectable sub-clusters (dialects) within languages?              |
| **RQ3** | Is algorithmic complexity class a recoverable geometric signal in embeddings?                  |
| **RQ4** | Do correct and buggy implementations cluster separately in embedding space?                    |

## Setup

Requires Python 3.10+ and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
```

For Ada-002 embeddings, copy `.env.example` to `.env` and add your OpenRouter API key:

```bash
cp .env.example .env
# Edit .env and set OPENROUTER_API_KEY
```

## Embedding Models

All scripts accept `--model MODEL` where MODEL is one of:

| Key         | Model                         | Type             |
| ----------- | ----------------------------- | ---------------- |
| `octen`     | Octen/Octen-Embedding-0.6B    | Local            |
| `bge_m3`    | BAAI/bge-m3                   | Local            |
| `unixcoder` | microsoft/unixcoder-base      | Local            |
| `codebert`  | microsoft/codebert-base       | Local            |
| `qwen3`     | Qwen/Qwen3-Embedding-0.6B     | Local            |
| `minilm`    | all-MiniLM-L6-v2              | Local            |
| `ada002`    | openai/text-embedding-ada-002 | API (OpenRouter) |

Pass `--model all` (the default) to run all models sequentially.

## Reproducing Results

Each RQ follows a 4-step pipeline: **embed → analyze → visualize → cross-model comparison**. Run the steps in order since each depends on the previous one.

### RQ1: Model-Dependent Language Family Structure

Embeds 21 linguistic features across 19 languages, performs hierarchical clustering (Ward linkage), and measures cross-model agreement via Spearman correlation of distance matrices.

```bash
# Step 1: Generate embeddings from linguistic feature snippets
uv run code/embedding.py --model all

# Step 2: Hierarchical clustering + cross-model comparison
uv run code/clustering.py --model all

# Step 3: Cross-model family stability (stable pairings, per-language family overlap)
uv run code/family_stability.py
```

Each dendrogram is cut into 5 families. The family overlap of a language is the Jaccard similarity between the families that contain it under two models, averaged over all model pairs.

Dataset: `datasets/family_clustering/` (19 languages x 21 features, the corpus released by Yun et al., FSE 2026).
Results go to `results/embeddings/` and `results/clustering/`.

### RQ2: Framework-Driven Dialects

```bash
uv run code/rq2/1_embedding.py --model all
```

### RQ4: Correctness Regions & Bug Patterns

```bash
uv run code/RQ4/1_embedding.py --model all
uv run code/RQ4/2_analysis.py --model all
uv run code/RQ4/3_visualize.py --model all
```

### RQ5: Retrieval-Augmented Generation with Buggy Code

Retrieval on HumanEvalFix (human-written bugs, 6 languages) and ClassEval (test-killed mutants),
LLM generation with a retrieved example, and execution against hidden tests.

```bash
# Step 0: build ClassEval correct/mutant pairs (needs datasets/RQ5/classeval/classeval.parquet)
uv run code/rq5/0_prepare_classeval.py

# Step 1: embed queries and documents (six local embedders + CLS-pooled CodeBERT/UniXCoder)
uv run code/rq5/1_embedding.py
uv run code/rq5/1_embedding.py --dataset classeval
uv run code/rq5/1_embedding.py --check          # reproducibility check against RQ4 embeddings

# Step 2: retrieval metrics, BM25 baseline, real-bug proximity, pooling ablation, example-test filtering
uv run code/rq5/2_retrieval.py

# Step 3: generation (needs OLLAMA_API_KEY in .env), then test execution and evaluation
# (one JavaScript test needs js-md5: npm install --prefix code/rq5)
uv run code/rq5/generate.py --llm ollama:gemma4:31b --lang python --contexts core
uv run code/rq5/generate.py --llm ollama:gemma4:31b --lang python --contexts needed
uv run code/rq5/3_evaluate.py --llm ollama_gemma4_31b
```

The study uses `gemma4:31b`, `gpt-oss:20b`, and `deepseek-v4.1-flash` on Ollama Cloud with
temperature 0, seed 0, and a 65,536-token output cap (34 DeepSeek responses reach it and count as failures). `code/rq5/execute.py` runs Python, JavaScript (Node), and Java (JDK 17)
programs; `python code/rq5/execute.py` validates the harness (all correct solutions pass, all buggy fail).

Datasets: `datasets/RQ5/humanevalpack/` (HumanEvalPack, Muennighoff et al., ICLR 2024) and
`datasets/RQ5/classeval/` (ClassEval, Du et al., ICSE 2024, plus our mutants).
Results go to `results/rq5/` (embeddings, rankings, generations, executions, metrics).

## Project Structure

```text
code/
  embedding.py           # Core embedding generation (shared by all RQs)
  clustering.py          # RQ1 hierarchical clustering & cross-model agreement
  family_stability.py    # RQ1 stable pairings and family overlap across models
  model_distance.py      # Cross-model distance matrix comparison
  rq2/                   # RQ2 pipeline (1_embedding → 4_cross_model)
  rq3/                   # RQ3 pipeline
  RQ4/                   # RQ4 pipeline
  rq5/                   # RQ5 retrieval-augmented generation pipeline

datasets/
  family_clustering/     # RQ1: 19 languages x 21 linguistic feature snippets
  RQ1/                   # Code-summary pairs (19 languages)
  RQ2/Extracted_Dataset/ # Framework-specific code snippets
  RQ3/                   # LeetCode problem files with complexity annotations
  RQ4/bugs.json          # Buggy-fixed code pairs

results/                 # All outputs (metrics JSON, plots, reports)
```
